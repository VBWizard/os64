# WebP import and characterization

Recorded 2026-10-10. This report covers the import/characterization milestone of
[the WebP design](../design/pending/WEBP.md). The subsequent bounded wrapper,
consumer integration and guest results are recorded in
[integration.md](integration.md).

## Pin and source audit

- libwebp 1.6.0, tag `v1.6.0`, commit
  `4fa21912338357f89e4fd51cf2368325b59e9bd9`.
- [Official release archive](https://storage.googleapis.com/downloads.webmproject.org/releases/webp/libwebp-1.6.0.tar.gz),
  SHA-256 `e4ab7009bf0629fd11982d4c2aa83964cf244cffba7347ecd39019a9e38c4564`.
- [Manifest](../../userland/libwebp/manifest.json): 71 pristine files, including
  upstream source-list Makefiles, release notes, COPYING, PATENTS and AUTHORS.
  The retained C/header notices identify Google copyright and refer to the
  upstream BSD license and patent grant. No additional source-license terms
  were found in this selection. The notice bundle preserves COPYING, PATENTS
  and AUTHORS verbatim and is checked by the audit.
- 27 common upstream translation units, seven SSE2 units, and one port CPU
  callback. Scalar comparison omits the seven SSE2 units. See the
  [import notes](../../userland/libwebp/README.md) for excluded components.

The freestanding audit passes using `x86_64-elf-gcc` 14.2.0. It compiles both
selections with warnings treated as errors, links the decoder entry-point
closure with section garbage collection, and inspects the resulting object.
Live undefined symbols are limited to `webp_port_malloc/calloc/free` and
`os64_memcpy/memmove/memset/memcmp`. No TLS symbols, encoder entry points,
pthread imports, CPU probing instructions, syscalls or AVX instructions were
found. The SSE2 variant contains its selected optimized decoder functions;
the scalar variant lacks those functions. Compiler-generated SSE2 remains
permitted in scalar x86-64 code.

Relocatable linking leaves orphan undefined symbol-table entries from discarded
functions, including an encoder palette helper. The audit strips unreferenced
entries before checking imports; relocation-required symbols remain. This
is an audit of the decoder core; the shared-library ABI and image packaging
are checked separately in [integration.md](integration.md).

The core uses synchronous worker callbacks with threading disabled. DSP
function pointers and initialization guards remain writable shared state.
Examples include `VP8DspInit`, `VP8LDspInit`, `VP8FiltersInit`, sampler,
upsampler, alpha and rescaler initialization, and private `InitGetCoeffs`.
The fixed CPU callback avoids CPU probing; it does not make these writes safe
under concurrent calls. The bounded wrapper described in
[integration.md](integration.md) serializes the decoder context and cleanup
before exposing the decoder to workers.

## Host measurements

[characterization.json](characterization.json) records fixture SHA-256 values,
pixel hashes, allocation counts, path bits, exact byte charges and timings.
[sanitized.json](sanitized.json) records the corresponding sanitizer run.
The host is WSL2 on an AMD Ryzen 9 3900X, with GCC 13.3.0 at `-O2`.
Fixtures are generated by our script using Pillow's libwebp 1.3.2 encoder,
plus constructed raw-alpha and maximum-width lossless containers. They do
not include downloaded artwork or third-party test images. Reproduction
requires Python 3 and Pillow with WebP encoding support.

Both variants decode to external BGRA storage with fancy upsampling enabled,
no scaling/cropping and no decoder threads. A temporary copy of `vp8l_dec.c`
contains probe callbacks that record transform selection and the 8-bit/32-bit
compressed-alpha path. The pristine import is unchanged. Every fixture has
matching scalar/SSE2 pixel hashes and zero live tracked temporary allocations
after cleanup. The synthetic 16,384-wide lossless image also matches the hash
calculated independently from its solid source pixels.

Memory values below are MiB. Timings are SSE2 / scalar milliseconds for one
decode, including lazy decoder initialization, excluding input loading and
pixel hashing. These are individual host samples, not stable performance

Path counters confirm that binary compressed alpha uses the optimized 8-bit
palette path, while gradient compressed alpha uses the 32-bit path. The
lossless gradient exercises predictor and cross-color transforms; noise
exercises subtract-green; the palette fixtures exercise color indexing.
The striped-noise fixture covers a less compressible raster at the pixel cap
while remaining below the encoded-input cap. This is path coverage, not
exhaustive transform combinations or adversarial entropy-table coverage.

The temporary allocator charges each request plus a 32-byte aligned bookkeeping
header. Output is charged separately and remains live throughout decode. The
input buffer, host allocator overhead, sanitizer memory, stacks and static
tables are excluded. Production bookkeeping must be included in its own
charge and its measured peaks checked against these results.

## Source accounting and selected limits

Let `N = width * height`, `W = width`, and `Np` be the number of packed pixels
after an optional palette transform. The following allocations explain why
JPEG's 128 MiB budget does not fit the supported WebP paths at 16 Mi pixels:

| Allocation | Source accounting |
| --- | --- |
| External output | `4*N` bytes. |
| VP8L 32-bit raster/cache | `AllocateInternalBuffers32b`: `4*Np + 4*17*W` bytes. A non-palette raster has `Np=N`. |
| VP8L 8-bit alpha raster | `AllocateInternalBuffers8b`: `Np` bytes. |
| Alpha planes with VP8 | `frame_dec.c:AllocateMemory` includes `N` bytes; `alpha_dec.c:AllocateAlphaPlane` separately allocates `N` bytes. Both contribute to the observed peak. |
| Predictor/cross-color transforms | Each auxiliary image holds `4*ceil(W/2^bits)*ceil(H/2^bits)` bytes, with `bits>=2`, at that transform's dimensions. |
| Entropy metadata | `ReadHuffmanCodes` decodes a subsampled group-index image, may allocate an index mapping, and allocates tree groups and growable Huffman-table segments. Counts depend on the bitstream. |
| Other temporary state | VP8 macroblock/row/filter caches, VP8L color caches, palette expansion, code lengths and decoder structs; these remain part of the charge. |

External output plus a non-palette lossless raster already needs 128 MiB
before row caches or transforms. For compressed alpha using the 32-bit path,
output, two alpha planes and the lossless raster total `10*N`, or 160 MiB
at 16 Mi pixels, before caches and entropy metadata. The measured 160.78 MiB
case agrees with that accounting. Entropy metadata can grow substantially;
these formulas are not a proof that every legal file fits a fixed budget.

Selected defaults for the wrapper are **20 MiB encoded input, 16 Mi pixels,
and 256 MiB output plus temporary allocation charge**. The largest observed
charge is 168,586,521 bytes, leaving 99,848,935 bytes (95.22 MiB) below the
budget. This headroom accommodates the measured ordinary paths; an input
requiring more must return `LIMIT`. Allocation-failure and budget-boundary
tests belong to the wrapper milestone. The probe measures allocations and
checks the resulting peak; it does not enforce the production budget.

With this default, Yonder's picture reservation must change from 148 MiB to
**276 MiB** (20 MiB input plus 256 MiB decode budget) when integration lands.
Six admitted picture jobs reserve 1,656 MiB of its 2,048 MiB pool budget,
leaving 392 MiB for other admitted jobs. Admission still depends on other
reservations. This is pool accounting, not a process-RSS bound, and does not
include pictures retained after work completes. No reservation was changed
in this milestone.

## Reproduction and remaining evidence

From the repository root, with the cross-compiler on `PATH`:

```sh
python3 tools/audit_webp.py --output /tmp/webp-core-audit
python3 tools/bench_webp_host.py --output /tmp/webp-characterization
python3 tools/bench_webp_host.py --output /tmp/webp-sanitized --sanitize
```

Use fresh output directories to regenerate fixtures. Existing generated
fixtures are cached; recorded hashes identify the exact files measured.
Encoder versions can change transform choices, so the script asserts the
required paths and stops if its fixtures no longer cover them.

Both scalar and SSE2 runs passed ASan, UBSan and LeakSanitizer for all ten
fixtures. The sandbox denied LeakSanitizer thread attachment with `EPERM`;
`LSAN_OPTIONS=verbosity=1:log_threads=1` exposed that error and `/proc/self/status`
reported `TracerPid: 0`. The successful sanitizer run used normal outside-
sandbox execution with `ASAN_OPTIONS=detect_leaks=1`. Leak checks were not
disabled.

This milestone does not establish malformed-container rejection, allocation
failure cleanup, concurrent wrapper behavior, public ABI/notice installation,
QEMU rendering or real-hardware speed. The subsequent
[integration](integration.md), [P5 benchmark](p5-benchmark.md), and
[browser stress](stress.md) reports supply evidence beyond this import
milestone and identify the remaining measurements. Host scalar/SSE2 agreement
alone is not an independent decoder oracle for lossy pixel correctness.
