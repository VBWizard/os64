crypto.subtle, tier 3

WEB_CRYPTO.md's tier 3, what fewer pages want, built in slices. Each line is a check against a published value or the behaviour Web Cryptography requires; another browser shows every line PASS, and so should yonder.

3a, derivation and AES-KW: HKDF (RFC 5869's test cases), PBKDF2 (RFC 6070's), deriveBits and deriveKey, and AES-KW (RFC 3394's) wrapping and unwrapping keys.

3b, the elliptic curves: ECDSA (RFC 6979's signatures) and ECDH (RFC 5903's exchanges) on P-256, P-384 and P-521, key pairs, and the spki, pkcs8, raw and JWK formats.

How long PBKDF2 holds the page


yonder does a derivation's work on the call (WEB_CRYPTO.md § 5), and the
page chooses PBKDF2's iteration count, so the page waits while it runs. Each
button derives 256 bits with PBKDF2 over SHA-256 at that many iterations and
prints the time. Sign-in pages use from about a hundred thousand to six
hundred thousand.

too. The button times each on every curve, five times, and prints the mean;
P-521 runs on BearSSL's generic code, so it is the slow one.
